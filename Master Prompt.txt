# MASTER PROMPT
# TELEGRAM SMART REMINDER INTERACTIVE
## Persistent, Timezone-Aware, Fault-Tolerant Reminder Bot

---

## 1. PROJECT OVERVIEW

Bangun sebuah aplikasi **Telegram Smart Reminder Interactive**, yaitu bot Telegram pribadi berbasis Python yang berfungsi sebagai asisten pengingat.

Bot harus memungkinkan pengguna membuat, mengelola, menjadwalkan, dan menyelesaikan reminder melalui percakapan interaktif di Telegram.

Aplikasi harus dirancang sebagai project yang:

- Persistent
- Timezone-aware
- Fault-tolerant
- Aman
- Modular
- Mudah diuji
- Mudah dipindahkan antar cloud provider
- Siap berjalan 24/7
- Tidak bergantung pada komputer lokal
- Cocok untuk deployment gratis atau always-free selama mungkin
- Layak dijadikan project portfolio software engineering/backend

Target penggunaan awal adalah personal use, tetapi arsitektur harus memungkinkan pengembangan menjadi multi-user application.

---

# 2. PRIMARY OBJECTIVES

Sistem harus mampu:

1. Membuat reminder melalui conversational flow.
2. Memproses waktu menggunakan input natural language.
3. Mendukung reminder sekali jalan.
4. Mendukung reminder berulang.
5. Menyimpan seluruh reminder secara persistent.
6. Memulihkan scheduler setelah aplikasi restart.
7. Menggunakan timezone pengguna.
8. Mengirim notification melalui Telegram.
9. Menyediakan interactive buttons ketika reminder muncul.
10. Mendukung complete, snooze, skip, dan disable.
11. Menampilkan daftar reminder aktif.
12. Menampilkan reminder hari ini dan reminder mendatang.
13. Menyimpan history/event reminder.
14. Menangani reminder yang terlewat ketika server mati.
15. Mencegah duplicate notification.
16. Menangani error dan retry.
17. Menyediakan health check.
18. Menyediakan logging.
19. Dapat dijalankan dengan Docker.
20. Dapat dipindahkan dari satu cloud provider ke cloud provider lain tanpa perubahan besar pada source code.

# 3. TECHNOLOGY STACK

Gunakan stack berikut kecuali ada alasan teknis kuat untuk menggantinya.

### Programming Language

Python 3.12+

### Telegram

python-telegram-bot versi stabil terbaru yang mendukung:

- Application
- ConversationHandler
- CallbackQueryHandler
- InlineKeyboardMarkup
- InlineKeyboardButton
- JobQueue jika diperlukan

Namun, gunakan APScheduler sebagai scheduler utama aplikasi.

### Scheduler

APScheduler versi stabil yang kompatibel dengan arsitektur async yang digunakan.

### Date Parsing

dateparser.

Gunakan untuk memahami input seperti:

- besok jam 8 pagi
- 30 menit lagi
- Jumat jam 19:00
- setiap Senin jam 08:00
- tanggal 10 Oktober jam 15:30

Jangan mempercayai hasil parser secara membabi buta. Semua hasil parsing harus divalidasi.

### Database

Development:

SQLite

Production:

PostgreSQL

Gunakan abstraction/database layer sehingga kode bisnis tidak bergantung langsung pada SQLite atau PostgreSQL.

### ORM

Gunakan SQLAlchemy jika sesuai.

### Migration

Gunakan Alembic untuk database migration.

### Web/API

Gunakan FastAPI hanya jika dibutuhkan untuk:

- health check
- webhook endpoint
- monitoring endpoint

Jangan membuat REST API kompleks jika tidak diperlukan.

### Container

Docker + Docker Compose untuk local development.

### Configuration

Environment variables menggunakan `.env` untuk development.

```text

   |
   v
python-telegram-bot
   |
   v
Conversation / Command Handler
   |
   v
Service Layer
   |
   +------------+
   |            |
   v            v

   |            |
   |            v
   |        Reminder Job
   |            |
   +------------+
                |
                v
          Telegram API
```

Ketika aplikasi startup:

```text

       |
       v

       v

       |
```

# 28. MISSED REMINDER RECOVERY

Kasus:

```text
07:50 server mati
08:00 reminder seharusnya dikirim
08:30 server hidup
```

Ketika startup:

1. Cari reminder yang seharusnya berjalan ketika server mati.
2. Tentukan apakah reminder masih valid.
3. Untuk one-time reminder, tandai sebagai missed/pending.
4. Berikan opsi kepada user:
   - Kirim sekarang
   - Skip
   - Reschedule
5. Untuk recurring reminder, hitung occurrence berikutnya.

Jangan kehilangan reminder hanya karena server restart.

---

# 29. IDEMPOTENCY

```text

```

atau database event state.

Jangan mengandalkan scheduler semata untuk mencegah duplicate execution.

# 51. ACCEPTANCE CRITERIA

Project dianggap berhasil jika:

### Basic

User dapat:

```text
/start
→ /reminder
→ mengisi data
→ confirmation
→ save
```

dan reminder tersimpan.

### Scheduling

Reminder dikirim pada waktu yang benar.

### Persistence

Jika bot restart:

```text
Reminder tetap ada.
```

### Recurring

Daily/weekly reminder tetap berjalan setelah restart.

### Snooze

Snooze menghasilkan waktu baru yang benar.

### Timezone

User Asia/Jakarta menerima reminder sesuai waktu lokal.

### Security

User tidak dapat mengakses reminder milik user lain.

### Recovery

Reminder yang terlewat ketika server mati ditangani secara jelas.

### Duplicate Prevention

Satu occurrence tidak menghasilkan duplicate notification.

### Deployment

Project dapat dijalankan dengan:

```bash
docker compose up
```

dan dapat dideploy ke VPS/cloud tanpa perubahan besar pada application code.
